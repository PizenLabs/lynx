# Benchmarks

Reproducible, grounded evidence for Lynx's retrieval quality, resource
behaviour, persistence lifecycle, and MCP reliability. Everything here is
deterministic: the corpus is checked in, tasks/truth are generated by a script,
and the harnesses print machine-readable metric lines.

## Running the whole suite

```bash
cd "$(git rev-parse --show-toplevel)"
benchmarks/scripts/run_validation.sh
```

Writes `benchmarks/reports/validation_<timestamp>.txt` containing:

1. **Discovery suite** — 135 grounded tasks across eight categories, scored with
   Precision@1/@3, Recall@5/@10, Hit@5 and MRR, with the hermetic fake provider
   and again with the real `bge-small-en-v1.5` embedder.
2. **Indexing scaling** — wall time and peak RSS for 50/100/200/400-file
   synthetic Rust repos.
3. **Lifecycle** — index time/RSS, cold-query latency percentiles, and proof that
   a query answers with the source tree deleted (no re-read, no re-index).
4. **Warm query latency** — p50/p95/p99 for every primitive inside one live MCP
   server, plus RSS before and after the lazy model load.
5. **MCP stress** — 200 sequential calls plus malformed frames, an unknown tool,
   a zero timeout, a huge query, and a restart, with latency percentiles and RSS.
6. **ripgrep baseline** — the same tasks scored with ripgrep and Lynx at the file
   level, for a fair comparison.
7. **Parser throughput** — the production single-pass parser versus the
   historical two-pass composition on the same source unit.

## Layout

```
benchmarks/
├── corpus/                 grounded multi-language corpora
│   └── auth-service/       Go + TypeScript + Python auth flow, with noise
├── tasks/discovery.json    task definitions (id, category, primitive, query)
├── truth/discovery.json    ground truth (primary + expected fqdns) by task id
├── scripts/
│   ├── gen_repo.py         deterministic synthetic repo generator
│   ├── gen_tasks.py        regenerates tasks/ + truth/ from the corpus
│   ├── run_validation.sh   orchestrates the whole suite
│   ├── lifecycle_probe.py  index/hydrate/cold-query latency + peak RSS
│   ├── warm_query_probe.py warm per-primitive latency + lazy-model RSS
│   ├── mcp_stress.py       sequential + adversarial MCP workload
│   └── rg_baseline.py      ripgrep-vs-Lynx comparison
├── reports/                generated reports (timestamped)
└── README.md
```

Legacy assets (`retrieval-corpus/`, `retrieval-truth.json`,
`scripts/run_hardening.sh`, the `profile_*` examples) are retained for the
earlier hardening measurements.

## Task categories

| Category | n | Primitive | What it measures |
|---|---|---|---|
| exact | 35 | `resolve` | bare symbol / fqdn resolution |
| lexical | 20 | `search` | keyword-overlap natural language |
| semantic | 20 | `search` | paraphrase with little lexical overlap |
| structural | 15 | `resolve` | exact coordinate lookup |
| relation | 15 | `relations` | call-graph / containment edges |
| context | 10 | `context` | compiled context packages |
| ambiguity | 10 | `resolve_all` | shared names + noise demotion |
| adversarial | 10 | `search` | empty/hostile/oversized input containment |

## Individual runs

```bash
# Discovery quality (hermetic fake provider — regression/stability only)
cargo run --release -p pizen-lynx-core --example validation_suite

# Discovery quality (real embeddings — the numbers that matter)
LYNX_REAL_EMBED=1 cargo run --release -p pizen-lynx-core --example validation_suite

# Warm per-primitive latency inside one live MCP server
python3 benchmarks/scripts/warm_query_probe.py target/release/lx benchmarks/corpus/auth-service

# Parser single-pass vs historical two-pass throughput
cargo run --release -p pizen-lynx-parser --example parser_bench

# Lifecycle / MCP / baseline against a built binary
cargo build --release -p pizen-lynx
python3 benchmarks/scripts/lifecycle_probe.py target/release/lx benchmarks/corpus/auth-service
python3 benchmarks/scripts/mcp_stress.py target/release/lx benchmarks/corpus/auth-service
python3 benchmarks/scripts/rg_baseline.py target/release/lx benchmarks/corpus/auth-service \
  benchmarks/tasks/discovery.json benchmarks/truth/discovery.json

# Regenerate tasks/truth after editing the corpus
python3 benchmarks/scripts/gen_tasks.py
```

## Notes

- The fake provider is deterministic but semantically meaningless; use it for
  regression/stability checks only. Use `LYNX_REAL_EMBED=1` for quality numbers.
- The real-embedding run loads `bge-small-en-v1.5` from
  `~/.cache/lynx/fastembed`.
- Cold-query latency from the CLI includes process start and ONNX model load;
  `resolve`/`relations`/`status` use a provider-free engine and do not load the
  model.
